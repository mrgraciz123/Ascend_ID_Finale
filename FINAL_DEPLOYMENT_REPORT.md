## 2. P0 Blocker Resolutions

### A. Firebase Permission Error
* **Root Cause:** When `onAuthStateChanged` triggers upon page load or role change, a brief window exists before the client-side Firestore SDK security context is synchronized with the new ID token. Calling `getDoc(doc(db, "users", currentUser.uid))` during this window resulted in Firestore security rule rejection (`Missing or insufficient permissions`).
* **Fix Applied:**
  * In [`src/app/issuer/layout.tsx`](file:///d:/Null%20to%20one/codebase/src/app/issuer/layout.tsx), added `await currentUser.getIdToken(true)` prior to role resolution.
  * In [`src/components/RoleSwitcher.tsx`](file:///d:/Null%20to%20one/codebase/src/components/RoleSwitcher.tsx), mirrored the token synchronization check before querying user roles.
  * Security rules in `firestore.rules` remain strictly protected and uncompromised.

### B. Complete Base Sepolia Elimination
* **Action:** Removed 140+ lines of dead `BaseSepoliaProvider` code from [`src/lib/blockchain.ts`](file:///d:/Null%20to%20one/codebase/src/lib/blockchain.ts).
* **Environment Cleaned:** Excised `BLOCKCHAIN_PRIVATE_KEY` and `NEXT_PUBLIC_BLOCKCHAIN_CONTRACT_ADDRESS` from `.env.local`.
* **Zero Occurrences:** A global scan across all `src/` files confirms zero occurrences of `Base Sepolia` or chain ID `84532`.

### C. W3C Proof Cryptographic Accuracy
* In [`src/app/api/credentials/anchor/route.ts`](file:///d:/Null%20to%20one/codebase/src/app/api/credentials/anchor/route.ts), updated the proof type specification from `JsonWebSignature2020` to `EcdsaSecp256k1Signature2019`, precisely aligning the metadata envelope with the Ethereum ECDSA secp256k1 signature generated by the backend.
